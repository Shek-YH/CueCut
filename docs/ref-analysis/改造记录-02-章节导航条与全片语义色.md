## 一、P0 章节导航条

对标视频验证的 retention 第一组件（视频 02 的顶部常驻导航条）。此前 CueCut 完全没有该层：`PackagingPlan.chapters` 有数据，但 `apply.ts` 转换时**直接丢弃**。

| 环节 | 文件 | 改动 |
|---|---|---|
| Schema | `src/project/schema.ts` | 新增 optional `chapters`、`project.chapterNav`（visible/position/showProgress）、`project.themePalette` |
| 透传 | `src/packaging/apply.ts` | 第二参数新增 `chapters`，归一化（过滤非法区间 → 按 startSec 排序 → 按 id 去重 → 只留四字段）；`App.tsx:775`、`externalBundle.ts:20` 两个调用点传入 |
| 场景产出 | `src/render/scene.ts` | 满足"有 chapters + nav 可见 + 时间落在 [首章起, 末章止)"时产出 `effectId='chapter-nav'`、`zIndex=90` 的 SceneItem（含 `activeIndex`、`chapterProgress`） |
| Canvas 预览 | `src/render/canvasRenderer.ts` | nav 分支：半透明横条 + 章节标题 + 当前章 accent 高亮 + 进度线 |
| 导出 | `src/export/renderer.ts` | 同语义的点阵实现（不改 5x7 字形系统） |

### 修复的缺陷（验证者用像素证据抓出）
**未排序 chapters 会让导航条整体消失**：`scene.ts` 原用 `chapters[0].startSec` / `chapters[last].endSec` 当"首章起/末章止"，而 `apply.ts` 的排序只保护主链路——手写或外部导入的 composition 会绕过，导致 `nav 存在=false`。
→ 已修：`scene.ts` 内对 chapters 做**防御性排序**（按 startSec, endSec），并补回归测试 `tests/render/chapter-nav.test.ts`（倒序输入仍产出 nav、activeIndex 正确、末章后不产出）。

## 二、P1 全片语义色

### 真根因（不是"动效各自为政"，是一刀切）
`apply.ts:100` 原本给**所有**包装动效同一个 `next.project.palette.accent`。因此整片只有一个颜色，谈不上色彩语义。

### 实现
- 新增 `src/packaging-theme/palette.ts`：**三层裁决**，上层有结果就不看下层
  | 层 | 依据 | 映射 |
  |---|---|---|
  | L1 | `semanticRole`（LLM 逐单元输出，最权威） | pain-point→warning(红)、hook→opportunity(绿)、evidence/conclusion→result(金)、definition/ordered-process/comparison/quote/neutral→method(蓝) |
  | L2 | `evidenceType` | number→result，其余→method |
  | L3 | catalog `effectFamilyId`/`visualTags`/`semanticTags` 关键词 | 兜底；层内命中多个时按 warning > opportunity > result > method |
  | 全未命中 | — | method（中性默认） |
- `apply.ts:109` 改为 `resolveSemanticAccent(...)`；`themePalette` 缺失时**完全退化成** `palette.accent`（历史行为不变）。

### 压测与修正（87 条真实 catalog）
修正 4 类**贪婪子串误判**：`con` 误中 `icon`、`bad` 误中 `badge`、`win` 误中 `window`（把图标/徽章/窗口卡错染成告警或机会色）、`attention-burst` 漏判为告警。
最终分布：warning 3 / result 23 / method 61 / **opportunity 0**（符合预期：opportunity 的正确入口是 L1 的 `hook`，卡片层本就没有"机会/收益"语义）。
