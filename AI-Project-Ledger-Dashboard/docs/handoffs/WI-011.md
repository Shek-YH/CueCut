## Delivered

- `POST /api/projects` accepts `{ "rootPath": "..." }` and returns `201` with the registered project, bootstrap kind, sanitized migration warnings and legacy file names.
- The server validates that `rootPath` is an existing directory, runs the existing conservative bootstrap decision, and reloads the resulting ledger through `LedgerStore` to enforce the projectId/root binding.
- Existing `.ai-ledger` projects are registered without rewriting their machine files. Legacy projects use the existing migration path; empty directories receive the existing seven-file skeleton.
- Successful additions are persisted through the Dashboard-owned `ProjectRegistry`, added to the running API map, and attached to a ready chokidar watcher. Subsequent allowlisted changes publish the existing SSE events.
- Add-project failures expose only stable generic messages; supplied paths, ledger contents and migration task titles are not returned in error responses.
